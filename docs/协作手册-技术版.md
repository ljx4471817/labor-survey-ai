# 协作手册 · 技术版

> 给写代码的同事。假设你会基本的 git 和 Python。
> 分支 / PR / 合并等**流程**看《协作手册-同事版》，这里只讲代码和项目本身。

## 快速开始（约 10 分钟）

```bash
git clone https://github.com/ljx4471817/labor-survey-ai.git
cd labor-survey-ai
python -m venv .venv && .venv\Scripts\activate   # Linux/macOS: source .venv/bin/activate
pip install -r backend/requirements.txt
copy .env.example .env    # Linux/macOS 用 cp；填入你自己的 API key（申请入口见模板注释）
python scripts/rebuild_all.py     # 构建知识库，首次必跑
cd backend && uvicorn app.main:app --reload --port 8001
```

浏览器开 http://localhost:8001/ 。登录需要白名单手机号，找维护者要测试号。

## 代码放哪

一个目录一个职责，新功能按层落位：

| 目录 | 放什么 |
|------|--------|
| `backend/app/api/` | 路由（每个业务域一个文件） |
| `backend/app/services/` | 业务逻辑 |
| `backend/app/rag/` | 检索（`pure.py` 纯函数 / `retriever.py` IO） |
| `backend/app/models/schemas/` | Pydantic 模型 |
| `backend/app/persistence/` | SQLite 读写 |
| `backend/static/` | H5 前端页面 |
| `backend/tests/` | 测试 |

三条规则：

1. 新功能**新建文件**，不改旧文件（bug fix 除外）
2. 纯函数必须有单测
3. 公共函数加类型注解

## 动手前的红线

- `.env`、任何 `.db`、API key、真实手机号：**永不提交**
- CI 在 **Linux + Python 3.11** 上跑：路径用 `pathlib`，`open()` 显式 `encoding="utf-8"`，别依赖本地时区
- 配置走环境变量，不硬编码

## 测试

```bash
cd backend && pytest tests/ -q
```

本地全绿再提 PR；CI 会自动再验一遍，绿了才能合并。

## 改知识库（如涉及）

`knowledge-base/qa/faq.json` 每条必须有：`source`、`category`、`keywords`≥3、`indicators`（非指标类用 `_indicators_topic`）。改完必跑：

```bash
python scripts/validate_faq.py
python scripts/rebuild_all.py
```

批量入库别直接改 faq.json，找维护者走五阶段流程。
