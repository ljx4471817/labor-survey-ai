# 劳动力调查 AI 助手 · 知识库更新与制度更新方法

> 最后更新：2026-07-15

## 概述

知识库更新有两条主线：

1. **知识库日常更新**：新增题库 / 新文档入库 → 走 `kb-update-workflow` skill（5 阶段流程）
2. **制度年度更新**：新版《劳动力调查制度》发布 → 走 `regulations-migrate` skill（自动迁移）

两条线最终都汇到同一个终点：`faq.json` + `eval_set.json` 同步更新、
Chroma/BM25 双索引重建、`run_eval.py` 全量回归。

---

## 一、知识库日常更新（kb-update-workflow）

> **触发场景**：拿到新题库 / 新讲义 / 新制度文档 / 新增 KB / 走入库 / 加题库 / 更新 KB。
> 调用 `.codex/skills/kb-update-workflow`（项目级，已 git 入仓）。

### 5 阶段流程

```
源文档 (PDF/Word)
    ↓ [1] ingest_source.py     入库 → markdown
markdown
    ↓ [2] extract_qa_pairs.py  抽取 Q&A
QA 候选集
    ↓ [3] detect_gaps.py       查重 + 缺口检测
待审核条目
    ↓ [4] 人工 review
approved-*.json
    ↓ [5] add_faq_entries.py   入库
faq.json (新增条目)
    ↓ 
validate_faq.py + build_kb.py + build_bm25.py --full + run_eval.py
```

### 关键脚本

| 文件 | 阶段 | 说明 |
|------|------|------|
| `scripts/ingest_source.py` | 1 | 新文档入库（docx/pdf → markdown） |
| `scripts/extract_qa_pairs.py` | 2 | 从 markdown 提取 Q&A（支持 `--mode llm`） |
| `scripts/detect_gaps.py` | 3 | 查重 + 缺口检测（`--candidates reports/extracted-qa-*.json`） |
| `scripts/add_faq_entries.py` | 5 | 审核通过的条目入库 |
| `scripts/patch_faq_from_eval.py` | 补 | 根据 eval 结果回写 KB |
| `scripts/patch2_faq_retrieval.py` | 补 | 改 KB 让检索命中的脚本 |
| `scripts/rewrite_docx.py` | 补 | 改写源 docx |
| `scripts/eval_from_docx.py` | 辅助 | 从 docx 提取题 + 构造 eval 集 |
| `scripts/build_eval_set.py` | 辅助 | 构造验证题库 |

### 调用方式

告诉 AI 一句即可：

> "新题库 `xxx.docx` 在 `D:/xxx/`，走入库流程"

skill 会按 5 阶段逐步执行，每个阶段产出明确、可中断、可审核。

## 二、制度年度更新（regulations-migrate）

> **触发场景**：每年 12 月初新版《劳动力调查制度》发布。典型改动：3-10 个指标增/删/位移，无大模块重组。
> 调用 `.codex/skills/regulations-migrate`（项目级，已 git 入仓）。

### 7 步流程

```
用户提供新制度 markdown 所在目录
    ↓ [1] 定位 markdown 文件（命名约定 + 兜底匹配）
[2] 提取新指标清单（regex + 表格 + 段落识别）
[3] 与 indicator_catalog.json 对比 → 输出 diff
    ↓
生成 migration_map.json 草稿
    ↓ [4] 用户审核（必看）
migrate_indicators.py dry-run → 影响报告
    ↓
用户确认
    ↓ [5] migrate_indicators.py --write
[6] validate_faq.py + build_bm25.py --full
[7] run_eval.py（全量回归，102/102 必须通过）
    ↓
如有 _indicators_removed 条目 → 用户决定 删/改写/保留
```

### 核心数据文件

| 文件 | 说明 |
|------|------|
| `knowledge-base/indicator_catalog.json` | **制度指标目录（63 个）**，按模块组织，新版制度权威指标列表 |
| `knowledge-base/migration_map.json` | **迁移映射**（每年一次）：renamed / removed / added |
| `knowledge-base/migration_map.example.json` | 模板（schema 参考） |
| `knowledge-base/qa/faq.json` | 知识库，每条的 `indicators` 字段关联制度指标 |
| `knowledge-base/qa/eval_set.json` | 验证题库（102 条），锁定 KB 答案质量 |

### 迁移脚本

| 文件 | 用途 |
|------|------|
| `scripts/migrate_indicators.py` | **核心迁移脚本**：dry-run 看影响 → --write 正式执行 |
| `scripts/validate_faq.py` | **校验脚本**：每次改 faq.json 后必跑，含 indicators 合法性 |
| `scripts/build_bm25.py` | **索引重建**：改 faq.json 后需 `--full` |
| `scripts/run_eval.py` | **回归验证**：门禁启用后需带 `--phone` 拿 token |
| `scripts/backfill_indicators.py` | **回填**：首次跑时把 indicators 字段填全 |
| `scripts/smart_backfill_indicators.py` | **语义回填**：用关键词打分处理 review 条目 |

### 调用方式

告诉 AI 一句即可：

> "制度变更，文档在 `D:\code\labor-survey-ai\knowledge-base\raw\markdown\2027\`"

skill 会自动接管 7 步流程。

### 完成标准

四项硬指标全过：
1. `indicator_catalog.json` 反映新版指标列表
2. `validate_faq.py` 0 errors
3. `build_bm25.py --full` 报告条目数 = faq.json 总数
4. `run_eval.py` 102/102 = 100%

### 关键红线

- dry-run 报告必须先看，不要直接 `--write`
- 删 KB 条目前必须问（即使是 `_indicators_removed` 标记的）
- 不启 Cloudflare Tunnel，用 `python -m uvicorn` 后台跑 8765 即可

## 六、自定义填报规范（贵阳调查队实操指引）

> 有些规则在制度原文里没有明文，但在实际调查工作中必须统一口径（常见于"大学生/在校生""外出/常住""特殊情况处理"）。这类条目按以下规范落库，避免与制度原文条目混淆。

### 字段约定

- `source` 字段统一写成 `贵阳调查队填报规范指引・<规则名>（制度依据：<对应制度段落> 结合 实际判断）`，用"实操指引"前缀一眼区分自建 vs 制度原文条目
- `indicators` 仍须填关联的 F/H 编号（靠 `indicator_catalog.json` 匹配）；规则属于多主题的用 `_indicators_topic: ['主题1', '主题2']`（字符串以 `_` 开头，校验器会忽略，检索层照常索引）
- `keywords` 必须覆盖调查员常问的自然语言词，建议 ≥ 6 条
- `eval_set.json` 锁定：新增 1 条 add 类 eval（`must_contain_any`）+ 1 条 correctness 类 eval（`should_not_contain` 拦截旧错误措辞）

### 入库流程（kb-update-workflow 的"自定义 Q&A 入库"分支）

1. 业务人员口述规则 → AI 按上述字段约定写出候选 JSON 条目
2. 跑 `python scripts/validate_faq.py` 字段完整性
3. `knowledge-base/qa/faq.json` 中追加条目（不要覆盖制度原文条目）
4. `python scripts/build_kb.py`（默认增量模式，只算新增/变动的条目）+ `python scripts/build_bm25.py --full`
5. 在 `eval_set.json` 加 1-2 条 eval 锁定 → 跑 `python scripts/run_eval.py --phone 13985000001` 全绿

### 示例

- `faq.json` id=355 → 大学生寒暑假回家 / 大四毕业后回家常住的登记口径
