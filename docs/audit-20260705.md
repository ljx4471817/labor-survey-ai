## 三、可读性评价

### ✅ 做得好的

1. **依赖方向清晰**：`api → services → rag/persistence`，不反向。`analytics` 独立，不依赖 embedding。
2. **纯函数隔离**：`aggregate_feedback` / `rrf_fuse` / `parent_matches` / `day_bucket_utc8` 全部无副作用。
3. **命名一致性**：`whitelist_db.py` / `query_log.py` 都是 `list_X` / `get_X` / `upsert` 风格。
4. **文档同步**：ADR 0009 记录 voice 停用，CONTEXT.md 统一领域词汇。
5. **schemas 子包**：按领域分组，`__init__.py` re-export 保持向后兼容。
6. **关键词可配置**：`data/scope_keywords.json` 热加载，加关键词不改代码。

### ⚠️ 仍可改善

1. **`chat.py` 5 层编排仍然最重**：scope→ambiguous→retrieve→LLM→refusal 在一个文件 ~185 行。已提取 `_handle_out_of_scope` / `_handle_ambiguous` / `_build_history_context` / `_detect_refusal` 四个辅助函数，但主流程仍在 `chat_endpoint` 里。
2. **`retriever.py` 仍含 IO + 并发调度**：`get_collection` / `embed_query` / `_vector_search` / `retrieve` 混合。纯函数已拆到 `pure.py`，但 IO 层仍然较重。
3. **`ThreadPoolExecutor(max_workers=4)` 硬编码**：并发能力固定。

## 四、可扩展性评价

### ✅ 扩展友好的

1. **新增 admin 端点**：只需在 `app/api/` 加一个 `xxx_admin.py`，`main.py` 加一行 `include_router`。
2. **新增检索模式**：加新源只需在 `retrieve()` 的 `_rrf_fuse` 前合并。
3. **新增反馈维度**：`aggregate_feedback` 是纯函数，加新聚合维度不影响现有输出。
4. **新增 Pydantic 模型**：在 `schemas/` 对应子文件加类，`__init__.py` re-export。
5. **新增范围关键词**：编辑 `data/scope_keywords.json`，无需改代码。

### ⚠️ 扩展瓶颈

1. **Chroma collection 全局单例**：`_CHROMA_COLLECTION` 模块级，无法热切换。
2. **`ThreadPoolExecutor(max_workers=4)` 硬编码**：DeepSeek 瓶颈（~45 并发连接）无法通过调 uvicorn workers 突破。
