# PRD: 劳动力调查月度测验系统

## 1. 产品概述

### 1.1 背景
劳动力调查 AI 知识库（labor-survey-ai）已解决"填报时遇到问题可检索解答"的需求。但有两类信息尚未有效同步到基层调查员：
1. **新上岗调查员**需要掌握的基础知识（已有线下培训 + KB，本期不做）
2. **月度工作提示**中的动态信息（审核要点、季节性关注点、填报口径微调）

### 1.2 核心定位
**不是**培训系统，**不是**知识库，而是"信息内化器"——把月度工作提示中需要调查员"记住并应用"的内容，通过 quiz 形式内化到头脑里。

### 1.3 目标
- 每月工作提示下发后，调查员在 7 天内完成 ≤7 道测验题
- 通过"做题→看解析→关联 KB"实现内化
- 管理员可追踪完成率

---

## 2. 用户角色

| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| **管理员** | 你自己 | 导入通知 → 审核要点 → 审核题目 → 下发 → 看完成率 |
| **调查员** | 社区工作人员（兼职） | 碎片时间答题 → 看解析 → 错了知道去哪查 |
| **区县管理者** | 中间层 | 被口头通知"让调查员去做题" |

---

## 3. 功能需求

### 3.1 管理端

#### 3.1.1 导入月度通知
- 上传 Word/docx 文件（支持附件）
- LLM 自动提取结构：
  - 时间安排（不入库）
  - 问卷要点（标记可出题）
  - 审核要点（标记可出题，附常见错误）
  - 填报口径微调（标记可出题）
- 输出：结构化要点列表，每点标注"建议出题"

#### 3.1.2 审核要点
- 管理员查看 LLM 提取的要点列表
- 操作：确认 / 删除 / 新增 / 编辑
- 每点标记关联的 KB 条目（从 faq.json 搜索）

#### 3.1.3 生成与审核题目
- 管理员确认要点后，LLM 生成题目：
  - 题干（基于要点情境化）
  - 4 个选项（1 正确 + 3 干扰项）
  - 解析（引用来源通知段落 + 关联 KB 条目）
- 管理员预览、编辑、确认
- 每月 ≤7 题

#### 3.1.4 下发
- 确认后一键下发
- 设置有效期（默认 7 天）
- 过期后锁定，不再可答

#### 3.1.5 完成率看板
- 本月测验：总人数 / 已做人数 / 完成率
- 按地区/分组筛选
- 个人明细：谁做了、谁没做、做对几题

## 4. 用户故事

### 4.1 管理员故事

1. 作为管理员，我每月收到上级下发的月度工作提示 docx 文件后，希望能一键上传到系统，让 LLM 自动提取出可出题的要点，这样我不用手动阅读整篇通知并逐条提炼。

2. 作为管理员，我希望看到 LLM 提取的要点列表，并能对每条进行确认、删除、新增或编辑操作，这样我可以纠正 LLM 可能的误提取。

3. 作为管理员，我希望系统能自动为每个要点关联 KB 条目（通过向量检索），这样调查员答错时可以直接跳转到对应的知识库条目查看原文。

4. 作为管理员，如果系统找不到匹配的 KB 条目，我希望看到"找不到对应 KB 条目"的提示，并且有一个文本框让我手动编辑解析内容，这样不会因为 KB 缺失而卡住出题流程。

5. 作为管理员，我希望确认要点后，LLM 能自动生成 4 选 1 的选择题（题干 + 4 选项 + 解析），这样我不用逐题手写。

6. 作为管理员，我希望预览 LLM 生成的题目，并能编辑题干、选项、答案和解析，这样我可以纠正 LLM 可能生成的错误答案或不合理干扰项。

7. 作为管理员，我希望一键下发测验，并设置有效期（默认 7 天），这样调查员在限定时间内完成。

8. 作为管理员，我希望看到完成率看板，包括总人数、已做人数、完成率，并能按地区筛选，这样我可以追踪各区县的完成情况。

9. 作为管理员，我希望看到个人明细（谁做了、谁没做、做对几题），这样我可以针对性提醒未完成的人。

10. 作为管理员，我希望过期的测验仍然可以作答（不强制锁定），但前端不再显示"未答题"提示，这样错过的人还有机会补做。

### 4.2 调查员故事

11. 作为调查员，我打开 H5 首页后，希望看到"本月测验"入口，并显示剩余天数和完成状态，这样我知道有任务要做。

12. 作为调查员，我希望在碎片时间（比如等公交时）能逐题作答，每题提交后立即看到对错和解析，这样我不用等全部做完才知道结果。

13. 作为调查员，答错时我希望解析里引用通知原文，并提示"相关知识点：KB 第 X 条"，这样我可以点进去看更详细的制度依据。

14. 作为调查员，全部做完后我希望看到总结"本月 X 题，你掌握了 Y 题"，这样我知道自己的掌握程度。

15. 作为调查员，我希望查看历史测验记录（按月），每题能看到我选了什么、正确答案是什么、解析是什么，这样我可以复习错题。

16. 作为调查员，即使测验已过期，我仍然可以查看历史答题记录，这样我可以回顾之前做过的题目。

### 5.5 状态机

#### 题目状态
```
draft → reviewing → published → expired
         ↑↓
       draft（打回修改）
```

| 状态 | 含义 | 可执行操作 |
|------|------|-----------|
| `draft` | LLM 生成，待审核 | 编辑、删除、提交审核 |
| `reviewing` | 管理员审核中 | 确认发布、打回修改 |
| `published` | 已下发，可答题 | 查看、过期自动流转 |
| `expired` | 已过有效期 | 查看历史，前端不再提示"未答" |

#### 测验月度状态
```
draft → published → expired → archived
```

| 状态 | 含义 |
|------|------|
| `draft` | 题目正在编辑/审核 |
| `published` | 已下发，调查员可见 |
| `expired` | 已过有效期，不再主动展示 |
| `archived` | 归档（12 个月后自动删除） |

### 5.6 数据存储

- 题目按月存储：`backend/data/quizzes/2026-08.json`
- 答题记录按月存储：`backend/data/quizzes/answers_2026-08.json`
- 导入记录：`backend/data/quizzes/imports.json`
- 要点记录：`backend/data/quizzes/keypoints.json`

### 5.7 索引设计

- 答题记录：按 `(user_phone, quiz_month)` 联合索引，支持快速查询个人月度答题
- 题目：按 `(month, seq)` 联合索引，支持按月按序查询
- 要点：按 `(import_id)` 索引，支持按导入批次查询

### 6.3 权限模型

- **admin 判定**：现有白名单数据库 `whitelist.db` 中增加 `role` 字段（`admin` / `user`），admin 可访问管理端 API
- **调查员隔离**：答题记录查询强制带 phone 参数，只能查自己的（从 token 中解析 phone）
- **管理端 API**：所有 `/api/admin/quiz/*` 端点需校验 `role == admin`，否则返回 403

### 6.4 文件上传与存储

- **存储方式**：内存处理，不持久化到磁盘
- **文件大小限制**：最大 10MB
- **允许类型**：`.docx` only
- **处理方式**：异步处理
  - 上传后立即返回 `import_id`
  - 前端轮询 `/api/admin/quiz/extract` 结果（每 3 秒一次，最长 120 秒）
  - 后端使用后台线程执行 LLM 提取
  - 超时（120 秒）后返回错误，管理员可重试

### 6.5 KB 关联机制

- **检索方式**：向量检索（复用现有 Chroma collection + embedding）
- **匹配阈值**：相似度 ≥ 0.6 视为匹配成功
- **匹配成功**：自动填充 `kb_ref.faq_id`、`kb_ref.question`、`kb_ref.score`
- **匹配失败**：
  ```
  前端显示："找不到对应 KB 条目"
  解析文本框：显示 LLM 生成的原始解析，管理员可手动编辑
  管理员可跳过该题或手动补充解析
  ```
- **解析生成**：LLM 生成解析时，自动引用通知原文段落作为依据

### 6.6 LLM Prompt 模板

#### Prompt 1：要点提取
```
你是劳动力调查专家。请从以下月度工作提示中提取可出题的要点。

## 输入
{notice_text}

## 输出格式
返回 JSON 数组，每项包含：
- section: 章节名称（"问卷要点"/"审核要点"/"填报口径微调"）
- content: 要点内容（一句话概括）
- common_error: 常见错误（如果有）
- suggest_quiz: 是否建议出题（true/false）

## 规则
1. 只提取需要调查员"记住并应用"的内容
2. 时间安排、通知对象等信息不提取
3. 每个要点聚焦一个知识点
4. 常见错误来自实际填报中的典型误判
```

#### Prompt 2：题目生成
```
你是劳动力调查出题专家。请根据以下要点生成 4 选 1 选择题。

## 输入
要点：{keypoint_content}
常见错误：{common_error}
来源段落：{source_quote}

## 输出格式
返回 JSON：
{
  "question": "题干（情境化，基于实际案例）",
  "options": {"A": "选项A", "B": "选项B", "C": "选项C", "D": "选项D"},
  "answer": "正确答案（A/B/C/D）",
  "explanation": "解析（引用来源段落，说明为什么对/错）"
}

## 规则
1. 题干基于实际填报场景，情境化出题
2. 干扰项来自常见错误，有迷惑性但明确错误
3. 解析必须引用来源段落原文
4. 答案唯一且确定
```

### 6.7 LLM 出题流程
```
1. 解析 Word → 提取文本（用 python-docx 库）
2. 分段 → 识别"审核要点""问卷要点"等章节
3. 调用 Prompt 1 → 提取要点
4. 管理员审核要点 → 确认/编辑/删除
5. 调用 Prompt 2 → 生成题目
6. 向量检索 faq.json → 关联 KB 条目（阈值 0.6）
7. 管理员审核题目 → 确认/编辑/删除
8. 一键下发 → 写入 2026-08.json
```

## 11. Out of Scope

本期不做：
1. **系统推送通知**：调查员通过区县管理者口头通知知晓测验
2. **错题重练**：限时模式，过期锁定，不提供错题本重做功能
3. **多人管理员**：单 admin 模式，不做多管理员权限分级
4. **题目随机顺序**：题目按固定 seq 展示，不做随机打乱
5. **答题倒计时**：不做单题限时，只限制月度总有效期
6. **成绩排名**：不做调查员间成绩排名
7. **新人培训**：新上岗调查员培训用现有 KB + 线下
8. **多语言**：仅中文
9. **离线模式**：必须在线答题
10. **文件版本管理**：同一月重复上传覆盖旧版本，不做历史版本保留

## 12. v4 泛化改造（2026-08-11）：按上层文件精神出题

### 12.1 背景
原系统仅支持「月度通知 docx → ≤7 题」。现泛化为**任意可提取文字的文件（Word/PPT/PDF）**出题，应用场景覆盖月度通知、新员工培训、季度/年度培训后测试等，定位从「月度测验」升级为「根据上层文件精神出题」。

### 12.2 关键决策
| 决策点 | 结论 |
|--------|------|
| 测验身份 | month 降级为可选标签（统一字段，无场景必填校验）；每次导入创建独立测验；排序按 created_at DESC；标题由管理员自由填写 |
| 场景字典 | 新增 scenes 表（名称唯一 + 启用状态）；管理端可自定义新增/停用（如「半年培训」）；测验存场景名称；统计/列表按场景分组 |
| 文件格式 | .doc/.docx/.wps（python-docx / 本机 COM）+ .pdf（pdfplumber 文字层）+ .pptx（python-pptx 文本框+备注）；不做 OCR（约定：只导入文字可直接提取的文件）；上限 20MB |
| 题量 | 生成时指定 1-20 题（schema 上限 20）；每要点最多 1 题，实际生成 min(count, 要点数)；要点不足时前端提示「要点不足，请返回补充/拆分要点」 |
| 要点提取 | LLM 提取不限制数量（用户按需勾选要点出题） |
| 删除 | 不做「重新导入」；管理端列表删除测验（仅 draft/reviewing，连带清要点/题目/目标/答题/导入） |
| 用户端 | 首页入口「我的测验」+ 待做套数角标；列表页 2 个 tab（待完成 / 已完成·过期）；卡片显示标题+场景标签+截止时间；做题页顶部显示场景标签；已完成可回看 |
| 存量数据 | 开发阶段直接删库重建（v4 schema，quiz.db 惰性建表） |

### 12.3 接口变更
- `POST /quiz/import`：新增 `title`（必填）、`scene`（必填）、`month`（可选）；文件类型扩至 .doc/.docx/.wps/.pdf/.pptx
- `GET /quiz/list`：新增 `scene` 筛选参数；返回含 `scene`
- `POST /quiz/generate`：新增 `count`（1-20，缺省=全部勾选要点）
- 新增：`GET/POST /quiz/scenes`、`POST /quiz/scenes/toggle`、`POST /quiz/delete`
- 用户端新增 `GET /quiz/my`：返回 `{todo, done}` 分组
