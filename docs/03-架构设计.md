## 二、数据流

### 2.1 在线问答流程（文字输入）

```
1. 用户在聊天页输入问题，点击发送
2. 小程序 utils/request.js 发起 POST /api/chat
   body: { message: "就业人口怎么判断", mode: "online" }
3. FastAPI 路由 (app/api/chat.py) 接收请求
4. RAG 引擎 (app/rag/retriever.py)：
   a. 调用 BGE API 把用户问题转成 embedding 向量
   b. 在 Chroma 中检索 Top-K（默认 K=5）相似文档
   c. 返回文档片段 + 元数据
5. Prompt 组装 (app/rag/prompts.py)：
   a. 加载系统提示词（角色 + 规则）
   b. 把检索结果格式化为上下文
   c. 拼接用户问题
6. 调用 DeepSeek API：
   a. 迭代 1 用整段返回（response.json()）
   b. 迭代 2 切 SSE 流式（response.iter_lines()）
7. 后端把结果（含引用来源）返回给小程序
8. 小程序聊天页渲染：
   a. 迭代 1 一次性展示
   b. 迭代 2 打字机效果
   c. 末尾显示"依据：xxx"
```

### 2.2 语音问答流程

```
1. 用户长按语音按钮录音，松开后停止
2. 小程序把音频文件上传到 POST /api/voice（multipart/form-data）
3. 后端调用腾讯云 ASR，返回识别文字
4. 前端展示识别结果，用户确认/编辑后点击发送
5. 走文字问答流程（2.1）
```

### 2.3 离线 FAQ 流程

```
1. 小程序启动时检测网络状态（wx.getNetworkType）
2. 离线模式（mode = "offline"）下：
   a. 用户输入走 utils/offline-faq.js
   b. 用 jieba.js 分词
   c. 与 FAQ JSON 计算 TF-IDF 相似度
   d. 返回 Top-3 预设答案
3. UI 顶部提示"当前为离线模式，联网后可获得更精准的回答"
4. 离线 FAQ 数据从后端 GET /api/faq/offline 缓存到本地（首次启动）
```

## 三、API 接口详细

### 3.1 POST /api/chat

**请求**：
```json
{
  "message": "就业人口怎么判断",
  "mode": "online"
}
```

**响应（迭代 1，整段）**：
```json
{
  "answer": "根据劳动力调查制度，就业人口的判断标准是...",
  "sources": [
    {"id": "001", "category": "就业状态判断", "source": "劳动力调查制度（2024版）第三章第二节"}
  ],
  "latency_ms": 2340
}
```

**响应（迭代 2，SSE 流式）**：
```
data: {"delta": "根据劳动力"}

data: {"delta": "调查制度"}

data: {"delta": "，就业人口的"}

...

data: {"done": true, "sources": [...]}
```

### 3.2 POST /api/voice

**请求**：multipart/form-data，字段 `audio` 为音频文件（PCM/MP3）

**响应**：
```json
{
  "text": "就业人口怎么判断",
  "duration_ms": 1230
}
```

### 3.3 GET /api/faq/categories

**响应**：
```json
{
  "categories": ["就业状态判断", "失业定义", "工作时间", "调查时点", ...]
}
```

### 3.4 GET /api/faq/search?q=就业

**响应**：
```json
{
  "results": [
    {
      "id": "001",
      "question": "一个人每周工作15小时，算不算就业人口？",
      "answer": "...",
      "category": "就业状态判断",
      "source": "...",
      "score": 0.87
    }
  ]
}
```

### 3.5 GET /api/faq/offline

**响应**：
```json
{
  "version": "2026-06-15-v1",
  "items": [
    {"id": "001", "category": "...", "question": "...", "answer": "...", "keywords": [...]}
  ]
}
```

## 四、模块职责

### 4.1 后端（backend/app/）

| 模块 | 职责 |
|------|------|
| `main.py` | FastAPI 应用入口、路由注册、中间件 |
| `api/chat.py` | `/api/chat` 路由、RAG 流程编排 |
| `api/voice.py` | `/api/voice` 路由、腾讯云 ASR 调用 |
| `api/faq.py` | FAQ 路由（categories / search / offline） |
| `rag/retriever.py` | 向量检索（Chroma + BGE API） |
| `rag/prompts.py` | Prompt 模板、上下文组装 |
| `rag/chunker.py` | 文档分块（迭代 1 不一定用，预留） |
| `models/schemas.py` | Pydantic 请求/响应模型 |
| `core/config.py` | 配置管理（环境变量） |
| `core/logger.py` | 日志（不记录用户问题原文，仅记录哈希） |

### 4.2 小程序（miniprogram/）

| 模块 | 职责 |
|------|------|
| `pages/index/` | 首页（快捷入口、推荐问题） |
| `pages/chat/` | 聊天页（核心） |
| `pages/faq/` | FAQ 分类浏览页 |
| `pages/settings/` | 设置页（缓存管理、网络状态） |
| `utils/request.js` | 网络请求封装（统一错误处理） |
| `utils/stream.js` | SSE/WebSocket 流式输出 |
| `utils/offline-faq.js` | 离线 FAQ 检索（jieba + TF-IDF） |
| `app.js` | 全局生命周期、配置初始化 |

### 4.3 知识库（knowledge-base/）

| 模块 | 职责 |
|------|------|
| `raw/` | 原始制度文档（不修改） |
| `qa/faq.json` | 结构化 QA 数据（手动维护） |
| `scripts/parse_docs.py` | PDF/Word 解析为原始文本（迭代 2+） |
| `scripts/build_kb.py` | QA JSON → Chroma 向量库 |

## 五、部署架构

### 5.1 单机部署（迭代 1-3）

```
腾讯云 2C4G 轻量服务器
├── Nginx（反向代理 + HTTPS）
│   └── api.example.com → 127.0.0.1:8000
├── FastAPI（uvicorn + systemd）
│   └── app/main.py
├── Chroma（本地文件存储）
│   └── data/chroma/
└── 腾讯云 ASR（外部 API）
```

### 5.2 部署流程

```bash
# 1. 服务器初始化
sudo apt update && sudo apt install python3.11 nginx certbot

# 2. 代码部署
git clone <repo> /opt/labor-survey-ai
cd /opt/labor-survey-ai/backend
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 3. 配置环境变量
cp .env.example .env
# 编辑填入 API Keys

# 4. 构建知识库
python ../scripts/build_kb.py

# 5. 启动服务
sudo systemctl enable /opt/labor-survey-ai/deploy/systemd/labor-survey-api.service
sudo systemctl start labor-survey-api

# 6. 配置 HTTPS
sudo certbot --nginx -d api.example.com
```

## 六、性能与可扩展性

### 6.1 性能目标（迭代 1）

| 指标 | 目标 |
|------|------|
| 端到端延迟（在线问答） | < 5s（整段返回） |
| 端到端延迟（流式首字） | < 2s |
| ASR 识别延迟 | < 3s |
| 离线检索响应 | < 200ms |
| 并发能力 | 10 QPS（2C4G 单机） |

### 6.2 扩展路径

- **数据量增长**（QA > 1000 条）：Chroma 切 Milvus（独立服务）
- **用户量增长**（> 100 并发）：后端多实例 + Nginx 负载均衡
- **业务扩展**（住户调查、价格调查）：知识库分库，路由层按业务分流
- **离线能力增强**：端侧 Embedding（小程序端跑 bge-small-zh）
