# 知识库规范

## 一、目标

知识库是回答质量的决定因素。本规范约束 QA 的录入格式、分类法、来源标注，确保：
- 检索召回率最大化
- 答案可追溯到制度依据
- 离线模式可直接消费

---

## 二、QA 数据格式

### 2.1 JSON Schema

每条 QA 是 `knowledge-base/qa/faq.json` 数组中的一个对象：

```json
{
  "id": "001",
  "category": "就业状态判断",
  "question": "一个人每周工作15小时，算不算就业人口？",
  "answer": "根据劳动力调查制度，就业人口的判断标准是：在调查参考周内，从事1小时以上有收入的劳动即为就业。每周工作15小时当然属于就业人口。需要注意的是...",
  "source": "劳动力调查制度（2026版）第三部分填表说明·问题10",
  "keywords": ["就业", "工作时间", "15小时", "就业人口"],
  "indicators": ["F10", "F11"]
}
```

### 2.2 字段说明

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| `id` | ✅ | string | 唯一标识，3 位数字字符串（001, 002, ...） |
| `category` | ✅ | string | 一级分类（见第三节分类法） |
| `question` | ✅ | string | 调查员可能的提问方式，**正式书面语**（与 `answer` 风格一致；不用口语/方言/网络语） |
| `answer` | ✅ | string | 标准答案，**正式书面语**（引用制度依据） |
| `source` | ✅ | string | 答案引用的制度来源（章/节） |
| `keywords` | ✅ | string[] | 用于离线检索的关键词，至少 3 个 |
| `indicators` | ⚠️ | string[] | 关联 `indicator_catalog.json` 中的 F/H 编号。**与 `_indicators_topic` 二选一** |
| `_indicators_topic` | ⚠️ | string | 非指标类条目用：调查时点/参考周、数据采集/PAD、抽样方案、入户沟通/调查技巧、统计法/保密、调查组织实施、表尾信息、登记对象规则、行业职业编码（9 选 1） |

> ⚠️ `indicators` / `_indicators_topic` 不是可选字段，是 schema v1 强制的。`scripts/validate_faq.py` 会警告未填条目。首次填充走 `backfill_indicators.py` + `smart_backfill_indicators.py`，制度变更后走 `migrate_indicators.py`。详见 ADR 0008。

### 2.3 字段填写规则

#### `id`
- 3 位数字字符串（"001" 到 "999"）
- 顺序递增，不复用
- 扩展业务时加前缀：`H001`（住户调查）、`P001`（价格调查）

#### `category`
- 见第三节分类法
- 一条 QA 只属于一个一级分类

#### `question`
- 用调查员**实际可能问的方式**写
- 包含典型数字、案例（如"15小时"、"学生打工"）
- 多个常见问法可用多个 QA（id 不同）覆盖

✅ 好的例子：
- "一个人每周工作15小时，算不算就业人口？"
- "在校学生暑期打工算就业吗？"
- "退休人员返聘算就业吗？"

❌ 不好的例子：
- "请解释就业人口的定义。"（太学术）
- "就业人口判断标准"（不是问句）

#### `answer`
- **必须**基于制度文档，不编造
- 简洁、直接、可操作
- 涉及具体指标判断时引用制度章节
- 长度建议 100-300 字
- 结尾如有补充说明（如"需要注意的是..."），可加但不超过 50 字

✅ 好的例子：
> 根据劳动力调查制度，就业人口的判断标准是：在调查参考周内，从事 1 小时以上有收入的劳动即为就业。每周工作 15 小时当然属于就业人口。需要注意的是，"有收入"包括实物报酬，如免费食宿折算。

❌ 不好的例子：
> 就业人口是一个比较重要的概念。一般来说，如果一个人从事了劳动，那么就算就业。具体请参考相关制度。（无依据、太泛）

#### `source`
- 精确到章/节：`劳动力调查制度（2024版）第三章第二节`
- 多源时用分号分隔：`制度A第三章；制度B附录二`
- 无法追溯时填 `待核实`，**且不应入知识库**——核实后再录

#### `keywords`
- 至少 3 个
- 包含核心名词、典型数字、相关场景
- 用于离线 TF-IDF 检索，命中率比在线 embedding 低，需靠关键词补偿

✅ 好的例子：`["就业", "工作时间", "15小时", "就业人口", "在校学生"]`

❌ 不好的例子：`["就业"]`（太少）、`["就业人口怎么判断"]`（这是句子不是关键词）

#### `indicators` / `_indicators_topic`
- **指标类条目**（涉及具体 F/H 编号判断）填 `indicators`，数组元素必须在 `knowledge-base/indicator_catalog.json` 已注册
- **非指标类条目**（程序/抽样/入户技巧/法规/调查组织等）填 `_indicators_topic`，从 9 个枚举值里选
- 不确定时打 `_indicators_review: true`，跑 `scripts/smart_backfill_indicators.py` 自动补
- 制度变更时**不要手工改 indicators 字段**，必须走 `migration_map.json` + `migrate_indicators.py`

✅ 好的例子：
- 指标类：`"indicators": ["F10", "F11"]`
- 非指标类：`"_indicators_topic": "入户沟通/调查技巧"`

❌ 不好的例子：
- `"indicators": ["F10", "入户技巧"]` — 混入非指标
- `"indicators": []` + `"_indicators_review": true` — 长期不解决（应在 24 小时内补）

## 三、分类法

一级分类（与离线 FAQ 页面分类一致）：

| 分类 | 范围 | 示例问题 |
|------|------|----------|
| 就业状态判断 | 就业/失业/不在劳动力的判断标准 | 就业人口定义、失业人口定义、退休算不算 |
| 工作时间 | 周工作小时数、加班、请假 | 15小时算就业吗、带薪假算工作时间吗 |
| 调查时点 | 参考周、调查周、登记时间 | 调查参考周是哪一周 |
| 调查对象 | 谁是劳动力调查对象 | 住户成员、外出人员、流动人口 |
| 行业职业 | 行业分类、职业分类 | 农民算什么行业、个体经营算什么 |
| 失业原因 | 失业的细分原因 | 季节性失业、被动失业、主动失业 |
| 填报规范 | 问卷填写规则 | 漏项怎么处理、涂改规则 |
| 编码规则 | 代码填写 | 行业代码、职业代码、原因代码 |
| 抽样方法 | 样本轮换、抽样框 | 户样本怎么抽、轮换周期 |
| 家庭关系 | 户主、配偶、子女判定 | 户主如何判定、外嫁女归属 |
| 收入相关 | 工资、经营收入、财产性收入 | 实物收入怎么折算、单位福利算不算 |
| 数据质量 | 核查、比对、异常处理 | 数据异常如何核实 |

**新增分类时**需更新：
1. `docs/04-知识库规范.md`（本文件）
2. `knowledge-base/qa/faq.json` 中已录入的 QA 同步重新分类
3. 重建向量库：`python scripts/build_kb.py --full`
4. 重建 BM25 索引：`python scripts/build_bm25.py --full`

> 注：当前 MVP 未提供分类浏览 API，分类主要服务于：(a) 人工评估/审计；(b) H5 上展示 mode 标签；(c) `data/feedback.jsonl` 的统计聚合。如未来要加 `GET /api/categories`，在 `app/api/faq.py` 新增路由即可。

## 四、录入流程

### 4.1 收集阶段

1. **原始素材**：从 `knowledge-base/raw/` 取制度文档
2. **问法采集**：从培训问答、调查员反馈、实际入户场景中提取
3. **答案整理**：从制度原文、培训资料中提取标准答案

### 4.2 录入阶段

1. 编辑 `knowledge-base/qa/faq.json`
2. 新 QA 加到数组末尾，id 递增
3. 每条 QA 必填字段都填，不留空
4. 来源追溯清楚，无法追溯的不录
5. **必填 `indicators` 或 `_indicators_topic`**：参考 `indicator_catalog.json` 选 F/H 编号，或从 9 个 topic 枚举里选。无法确定时打 `_indicators_review: true`，跑 `smart_backfill_indicators.py` 兜底

### 4.3 验收阶段

每批录入后做：
1. **数量检查**：JSON 解析成功，字段完整
2. **字段校验**：`python scripts/validate_faq.py`（含 indicators 合法性）
3. **向量入库**：`python scripts/build_kb.py`（默认增量；模型升级时用 `--full`）
4. **BM25 重建**：`python scripts/build_bm25.py --full`
5. **检索测试**：用 5-10 个典型问题检索，Top-3 应包含预期 QA
6. **回归验证**：`python scripts/run_eval.py --phone 13985000001`（确认未退化，102/102 必须通过）

### 4.4 增量更新

新增 QA 不需要重建向量库——`scripts/build_kb.py` 应支持增量：

```bash
# 全量重建
python scripts/build_kb.py --full

# 增量（默认；只处理新增/修改的 QA）
python scripts/build_kb.py
```

QA 与制度 chunk 共用 Chroma collection。`build_kb.py --full` 只重建 QA，
`build_chunks.py --full` 只重建 chunk，二者不得互相删除；详见 ADR 0010。

### 4.5 制度变更同步

每年 12 月初新版制度发布后，**优先调用 `regulations-migrate` skill**（`.codex/skills/regulations-migrate/`），整条链路标准化。详见 ADR 0008 与 `知识库更新与制度更新方法.md`。

## 五、质量红线

下列情况**禁止**入知识库：

1. **无来源依据**：制度文档中找不到对应条款
2. **主观判断**：答案含"我认为"、"一般情况"等非制度性表述
3. **涉及居民个人信息**：哪怕是脱敏后的案例
4. **过时制度**：已被新制度替代的旧版答案
5. **与其他 QA 矛盾**：未与已有 QA 对齐口径
6. **未填 indicators / _indicators_topic**：schema v1 强制要求，未填会被 `validate_faq.py` 警告
7. **indicators 出现未注册编号**：必须先在 `indicator_catalog.json` 注册才能用

发现问题立即：
1. 删除该 QA
2. 在 `docs/04-知识库规范.md` 附录「变更日志」中记录
