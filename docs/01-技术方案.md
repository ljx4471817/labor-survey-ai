## 一、项目背景

国家统计局调查队系统承担劳动力调查、住户调查、CPI 采价等民生数据采集工作。调查员（特别是辅助调查员）在入户调查时，经常遇到指标理解、填报规范等方面的问题，需要即时获得准确的指导。

目前的解决方式主要依赖：
- 培训课件和制度文档（纸质或 PDF，不便携、检索困难）
- 电话咨询业务骨干（时效性差、占用骨干精力）
- 个人经验判断（一致性难以保证）

本项目旨在开发一个**基于 RAG（检索增强生成）的 AI 助手**，以微信小程序为载体，让调查员在入户时可以通过文字或语音描述问题，系统检索知识库后给出准确的填报指导。

---

## 二、产品定位

- **用户**：劳动力调查辅助调查员（后续可扩展到住户调查、价格调查等业务）
- **场景**：入户调查时遇到指标疑问，需要即时查询
- **核心价值**：把"查文档+打电话"变成"问 AI 秒回"
- **载体**：微信小程序（扫码即用，无需安装）
- **交互方式**：文字输入 + 语音输入 + 离线 FAQ 搜索

### 3.2 技术选型

| 组件 | 选型 | 说明 |
|------|------|------|
| **前端** | 微信小程序原生开发 | 用户无需安装，扫码即用 |
| **后端框架** | Python FastAPI | 异步高性能，RAG 生态成熟 |
| **向量数据库** | Chroma（MVP）→ Milvus（生产） | Chroma 轻量适合 MVP，Milvus 适合大规模 |
| **大模型 API** | DeepSeek V4 | 中文能力强、成本低 |
| **Embedding 模型** | BAAI/bge-large-zh-v1.5 | 开源中文向量模型，可本地部署 |
| **语音识别** | 腾讯云 ASR / 讯飞（**2026-06-21 已停用**，输入法自带） | 与微信生态兼容，延迟低 |
| **分词** | jieba | 离线 FAQ 检索用 |
| **服务器** | 腾讯云轻量应用服务器 2C4G | 与微信同生态，备案方便 |
| **前端离线检索** | jieba.js + TF-IDF（纯前端） | 无网络时的降级方案 |

### 3.3 核心功能流程

#### 在线模式（有网络时）

```
用户输入（文字/语音 — **语音 2026-06-21 已停用**）
  │
  ├─ ~~语音 → 腾讯云 ASR → 文字~~
  │
  ▼
RAG 检索
  │
  ├─ 文字 → Embedding → 向量数据库检索 Top-K 相关文档
  ├─ 附加：关键词匹配 FAQ
  │
  ▼
Prompt 组装
  │
  ├─ 系统提示词（角色设定 + 约束）
  ├─ 检索到的知识库片段
  ├─ 用户问题
  │
  ▼
调用 DeepSeek API（流式输出）
  │
  ▼
前端展示回答（打字机效果）
```

#### 离线模式（无网络时）

```
用户输入（文字）
  │
  ▼
本地 FAQ 检索
  │
  ├─ jieba 分词 → TF-IDF 相似度匹配
  ├─ 返回最相关的 1-3 条 FAQ
  │
  ▼
直接展示预设回答
（提示：当前为离线模式，联网后可获得更精准的回答）
```

## 四、知识库设计

### 4.1 知识来源

| 来源 | 内容 | 格式 |
|------|------|------|
| 劳动力调查制度 | 调查方案、指标定义、抽样方法 | PDF/Word |
| 填报规范 | 问卷填写说明、编码规则、逻辑关系 | Word |
| 常见问题 | 调查员高频提问及标准回答 | 结构化 QA |
| 培训课件 | 如《劳动力调查13个家庭画像学指标》等 | PPT/Word |
| 制度解读 | 国家统计局下发的制度解释、答疑文件 | PDF/Word |

### 4.2 知识库结构（QA 对格式）

```json
{
  "id": "001",
  "category": "就业状态判断",
  "question": "一个人每周工作15小时，算不算就业人口？",
  "answer": "根据劳动力调查制度，就业人口的判断标准是：在调查参考周内，从事1小时以上有收入的劳动即为就业。每周工作15小时当然属于就业人口。需要注意的是...",
  "source": "劳动力调查制度（2024版）第三章第二节",
  "keywords": ["就业", "工作时间", "15小时", "就业人口"]
}
```

### 4.3 离线 FAQ 预估

预整理 200—500 条高频 QA，缓存到小程序本地（约 1—2MB），覆盖 80% 的常见问题。

## 五、小程序前端设计

### 5.1 页面结构

```
小程序
├── 首页（简洁入口 + 快捷问题推荐）
├── 聊天页（核心页面）
│   ├── 文字输入框
│   ├── 语音输入按钮（长按录音）
│   ├── 消息列表（用户问 + AI 答）
│   └── 流式输出（打字机效果）
├── FAQ 页（分类浏览常见问题，支持离线）
└── 设置页（网络状态、缓存管理）
```

### 5.2 关键交互

- **语音输入**：长按录音按钮 → 录音 → 上传后端 ASR → 返回文字 → 用户确认后发送
- **流式输出**：使用 `wx.request` 的 `enableChunkedTransfer`（基础库 2.20+）实现
- **离线提示**：检测网络状态，无网络时自动切换到离线 FAQ 模式，并提示用户
- **知识来源标注**：AI 回答后附带引用来源（如"依据：劳动力调查制度第X章第X节"）

### 5.3 微信小程序技术限制

| 限制项 | 值 | 应对方案 |
|--------|-----|---------|
| 主包大小 | 2MB | 核心代码放主包，FAQ 数据放分包 |
| 总包大小 | 20MB（分包后） | 足够 |
| 本地存储 | 10MB | FAQ + 缓存足够 |
| 请求超时 | 默认 60s | RAG + LLM 响应需控制在 30s 内 |
| WebSocket | 支持 | 流式输出可用 WS 或 chunked transfer |
| 域名白名单 | 必须 HTTPS | 后端需配 SSL 证书 |

## 六、后端 API 设计

### 6.1 核心接口

```
POST /api/chat
  - body: { "message": "用户问题", "mode": "online"|"offline" }
  - response: SSE 流式返回 AI 回答

POST /api/voice（**2026-06-21 已停用**）
  - body: 音频文件（PCM/MP3）
  - response: { "text": "识别出的文字" }

GET /api/faq/categories
  - response: FAQ 分类列表

GET /api/faq/search?q=关键词
  - response: 匹配的 FAQ 列表

GET /api/faq/offline
  - response: 全量离线 FAQ（供小程序缓存）
```

### 6.2 RAG Prompt 模板

```
你是劳动力调查填报指导助手。你的知识来自国家统计局劳动力调查制度和相关培训材料。

规则：
1. 只基于提供的知识库内容回答，不要编造信息
2. 如果知识库中没有相关内容，明确告知用户"建议咨询业务主管"
3. 回答要简洁、直接、可操作
4. 涉及具体指标判断时，引用制度依据

知识库检索结果：
{retrieved_context}

用户问题：
{user_question}
```

## 七、开发路线（MVP）

- [ ] 收集劳动力调查制度文档（PDF/Word）
- [ ] 整理 200—500 条结构化 QA 对
- [ ] 标注关键词、分类、来源
- [ ] 导出为 JSON 格式

### Phase 2：后端 RAG 服务（1—2 周）

- [ ] 腾讯云服务器部署（Ubuntu + Python 3.11）
- [ ] FastAPI 框架搭建
- [ ] 文档加载 → 分块 → Embedding → 存入 Chroma
- [ ] RAG 检索 + DeepSeek API 调用
- [ ] 流式输出接口（SSE）
- [ ] 语音识别接口对接

### Phase 3：小程序前端（2—3 周）

- [ ] 注册个人小程序，获取 AppID
- [ ] 聊天界面开发（消息列表 + 输入框 + 流式渲染）
- [ ] 语音输入功能
- [ ] 离线 FAQ 页面 + 本地缓存逻辑
- [ ] 网络状态检测 + 离线/在线模式自动切换

### Phase 4：测试与优化（2—4 周）

- [ ] 处室内小范围测试
