# ADR 0018 — 反馈复核闭环 v2 与近一月热点问题

> 状态：已采纳（2026-08-31）
> 触发：管理员需要结构化复核负面反馈；前端示例问题需要反映真实使用热度。
> 决策者：开发者 + 管理员需求确认

## 背景

ADR 0006 的反馈闭环解决了"标记已处理"，但存在三个缺口：

1. 负面反馈只有"不采纳"按钮，没有结构化修正建议（正确答案 + 依据），管理员看到 👎 后仍需自行判断哪里错了。
2. "使用侧发现 / KB 改进候选"入口混杂了多种来源（out_of_scope、低相似度等），实际运营中改进唯一有效来源是用户提交的负面反馈修正建议。
3. 前端空状态的示例问题写死在代码里，无法反映近一月真实热点。

## 决策

### 反馈复核 v2

**前端（index.html）**：RAG 命中的回答把"不采纳"改为"答案不正确，反馈"按钮 → 弹窗必填"正确答案"（≥10 字符）与"依据"（≥10 字符）。同一 `phone + request_id` 仅可提交一次（服务端 409）。

**后端**：`feedback_resolved.jsonl` 每行记录 `{record_id, action, ts, reviewer_phone, reviewer_name}`。action ∈ `accepted / rejected`，最新复核事件生效，完整历史保留在 `history` 字段。

**看板（dashboard.html）**：KB 优化 tab 重构为复核队列，三个 tab（待处理 / 已采纳 / 不采纳）。每条明细显示完整手机号、姓名、区域五级、用户问题、原答案、正确答案、依据、复核历史。改进候选（`improvement_candidates`）仅来自用户负面反馈修正建议，按 top-1 QA 聚合。

### 近一月热点问题

**数据链路**：`query_log` 新增 `top_qa_id` 列（记录 top-1 命中的 QA id）→ `top_qa_stats()` 按近 30 天成功 RAG 查询聚合（排除保护号）→ `build_hot_questions()` 按 `user_count >= 2` 排序 → 映射 KB 标准问法 → 前端空状态展示。

**标准问法映射**：QA id 三位零填充为 key，从 `knowledge-base/qa/faq.json` 读取当前标准问法。无热点或聚合失败时降级到 `backend/data/default_questions.json` 运营维护列表，配置异常再降级到代码内置应急问法。

**缓存**：进程内 30 分钟 TTL，`/api/chat/hot-questions` 直接返回缓存或重新聚合。

## 影响

- 反馈质量从"👎 无理由"提升为"结构化修正建议"，KB 维护者可直接按依据定位制度原文
- 复核操作纯标记，不自动修改 KB，最终决策仍由管理员完成
- `dashboard.html` 移除"使用侧发现" tab，信息收敛
- 前端示例问题从静态列表变为动态聚合，用户看到的是真实热点
