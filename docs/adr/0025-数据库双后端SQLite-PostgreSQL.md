# 0025 · 数据库双后端（SQLite / PostgreSQL）

## 背景

后端原以 4 个 SQLite 文件存数据（whitelist / conversations / query_log / quiz），单机版够用，但多人并发写入受 SQLite 单写者限制，且无法支撑后续全省多节点部署。直接换 PostgreSQL 又要求"停机窗口内可随时切回 SQLite"，回滚不能依赖回滚代码。

## 决策

1. **引入双后端适配层 `backend/app/persistence/db.py`**。所有持久化模块只经它建连；它只做三件事：按 DSN 前缀自动判定后端（`postgres://` / `postgresql://` → psycopg 3，其余 → SQLite 文件路径）、占位符转换（PG 侧 `?` → `%s`）、行对象统一（按列名 / 按序号取值）。不引入 ORM / SQLAlchemy。
2. **后端选择走环境变量**：`LSX_DB_WHITELIST` / `LSX_DB_CONVERSATIONS` / `LSX_DB_QUERY_LOG` / `LSX_DB_QUIZ`，值为 PG DSN 或 SQLite 路径；未设置时回落现有 SQLite 默认路径。切库 = 改 `.env` + 重启；回滚 = 改回 `.env` + 重启，不回滚代码。
3. **每模块双套显式 DDL**（`_SCHEMA_SQLITE` / `_SCHEMA_PG`），不做自动方言翻译。PG 自增主键用 `GENERATED BY DEFAULT AS IDENTITY`（非 ALWAYS）：迁移脚本需显式写入 SQLite 带来的 id。
4. **线程局部连接**。适配层内部每线程一份底层连接（threading.local），对外保持"一个连接对象到处用"；app/ 中大量 sync def 端点跑在线程池，psycopg 连接不支持跨线程并发。
5. **PG 侧语句级 SAVEPOINT**。SQLite 单条语句失败不毒化事务，PG 会 abort 整个事务；为对齐"列已存在则跳过"的幂等迁移语义，每条语句包 SAVEPOINT，失败 ROLLBACK TO SAVEPOINT 后抛统一异常。
6. **统一异常族**：业务代码捕获 `db.OperationalError / IntegrityError / Error`。SQLSTATE 42 类（缺表 / 缺列 / 重复列 / 语法错）映射为 OperationalError，与 SQLite 语义对齐。
7. **`INSERT OR IGNORE` 双套 SQL**：PG 用 `ON CONFLICT DO NOTHING`（不指定冲突目标列 = 捕获任意唯一约束冲突）。
8. **一次性迁移，不做双写**。`backend/scripts/migrate_sqlite_to_pg.py` 默认 dry-run、只读 SQLite（mode=ro）、表自动发现、apply 后行数 + 校验和双比对、setval 重置 IDENTITY 序列、TRUNCATE 全量重插幂等；任一校验不一致退出码非 0。
9. **全国场景预留，不做超纲**：连接创建集中在 db.py（将来换连接池只改这里）、全部 SQL 参数化、时间字段保持 UTC+8 文本（不换 timestamptz）、只用标准 SQL。读写分离 / 分片 / pgbouncer / ChromaDB 迁移留到阶段三。

## 后果

- 服务器侧停机窗口迁移操作与验证步骤见 `docs/pg-migration.md`；SQLite 文件在迁移期间不被删除或修改，回滚 ≤ 5 分钟。
- `retrieval_score` / `kb_score` 在 PG 侧为 `DOUBLE PRECISION`（PG 的 REAL 是 float4 会丢精度）。
- 适配层 SQLite 分支统一启用 WAL + busy_timeout=5000 + timeout=10（query_log.db 原本未开 WAL，现统一，行为兼容）。
- `db.connect` 按 target 缓存包装对象；测试换库需重置模块级 `_conn` 或调用各模块 `reset_conn()`。
