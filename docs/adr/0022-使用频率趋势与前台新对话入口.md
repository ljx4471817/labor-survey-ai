# ADR 0022：使用频率趋势与前台新对话入口

## 状态

**已采用（2026-09-07）**。

## 背景

管理端已有按用户聚合的使用情况查询，但缺少按日变化的趋势视图，无法快速判断近期使用热度。前台进入历史会话后也没有不刷新页面就回到新对话的明确入口。

## 决策

### 1. 使用频率以每次 `/api/chat` 请求为统计单位

- 不按会话去重，也不按 `mode` 过滤；`rag`、`out_of_kb`、`out_of_scope`、`ambiguous` 都算一次对话。
- 数据源沿用 `query_log`，不新增表、不复制统计数据。
- 时间按 UTC+8 自然日聚合，窗口包含当天；支持 7 天和 30 天，缺失日期补 0。
- 业务管理员沿用 `region_scope` 限定省 / 市 / 县；系统管理员看全量。
- Dashboard 折线图不跟随使用情况查询筛选条件，固定展示登录管理员的辖区范围。

### 2. 前台提供「开始新对话」显式入口

- 仅在当前已加载会话时显示，避免新会话状态下的冗余操作。
- 点击后清空当前聊天区与会话 ID，保留输入框内容。
- 回答请求进行中禁用，避免请求归属到错误会话。
- 历史抽屉中的「新对话」复用同一个动作，关闭抽屉后再回到新会话。

## 影响

- `query_log` 的写入完整性决定趋势图准确性；不要绕过 chat 路由旁路写日志。
- 趋势统计不做日表或物化聚合；处室自用规模下 SQLite 按日聚合足够，后续并发显著上升时再优化。
- 前端切换 7/30 天时校验响应仍属于当前选择，避免旧请求晚返回覆盖图表。
