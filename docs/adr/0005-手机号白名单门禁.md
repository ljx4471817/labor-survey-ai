# ADR 0005：手机号白名单门禁

## 状态

**已采用（2026-06-24）**

## 背景

H5 经 Cloudflare Tunnel quick 模式（ADR 0004）暴露公网后，**无任何身份校验**。访问控制依赖 trycloudflare.com 随机 URL 不外泄（ADR 0004 风险表 line 73-77），URL 一旦泄漏任何人能用。

需要在不引入认证库依赖的前提下，加一道轻量门禁。

## 决策

**HMAC-SHA256 签名 token + 手机号白名单 JSON，热加载、零外部依赖。**

### 数据流

```
浏览器打开 /
  ↓ 无 token
  ↓ 渲染 login.html（隐藏 index.html）
[login.html] 输入手机号 → POST /api/auth/login {phone}
  ↓
  ├─ 不在 whitelist → 401 "手机号未授权"
  └─ 在 whitelist → 返回 {token, expires_at}
      ↓
      ↓ 浏览器存 localStorage.lsx_token
[token] 跳转 / → index.html 显示
  ↓ 每次 fetch 自动加 Authorization: Bearer <token>
[/api/chat / /api/feedback / /api/admin/* / /dashboard]
  ↓ Depends(require_user)
  ├─ token 校验失败 / 过期 → 401
  └─ 通过 → 处理请求
```

### Token 格式

- 算法：HMAC-SHA256，密钥从 `LSX_AUTH_SECRET` 读；缺则启动时随机生成（每次重启失效，仅 dev）
- Payload：`<phone>|<exp_unix>|<nonce>` → base64url
- Token：`<base64url(payload)>.<base64url(sig)>`
- TTL：24 小时（默认，`LSX_TOKEN_TTL_HOURS` 可调）
- 校验：`hmac.compare_digest` 防时序攻击 + exp 检查

**不引入 `pyjwt` 等外部库**：stdlib `hmac` + `hashlib` 够用，避免依赖膨胀。

### 白名单热加载

- 文件：`backend/data/whitelist.json`，格式 `{"phones": ["13800138000", ...]}`
- 读取时记 `st_mtime_ns`，下个请求 mtime 变化则重载
- 用 `functools.lru_cache(maxsize=1)` 包装读取函数，cache key 用 mtime
- 文件不存在或坏 → 返回空集（拒绝所有登录，不抛异常拖垮服务）

### 全栈门禁

`backend/app/main.py` 在 router 层加 `Depends(require_user)`：

```python
app.include_router(chat_router, prefix="/api", tags=["chat"], dependencies=[Depends(require_user)])
app.include_router(feedback_router, prefix="/api", tags=["feedback"], dependencies=[Depends(require_user)])
app.include_router(admin_router, prefix="/api/admin", tags=["admin"], dependencies=[Depends(require_user)])
app.include_router(auth_router, prefix="/api/auth", tags=["auth"])  # 公开
```

`/dashboard`、`/login`、`/` 静态页本身不校验 token，但页面内的 fetch 调用会触发 401 → 前端 `handle401` 清 token + 跳 `/login`。

### 前端改动

- `backend/static/login.html`：单页登录（手机号输入 + 提交）
- `backend/static/common.js`：`authHeader()` + `handle401()` 共享工具
- `localStorage` key：`lsx_token`、`lsx_token_expires_at`
- 首页不暴露登录入口（保持低调）

## 考虑过的备选

| 方案 | 否决理由 |
|------|----------|
| 短信验证码 | 需第三方短信服务 + 用户学习成本，与"简单门禁"目标不符 |
| OAuth / 微信扫码登录 | 依赖第三方平台，单位内部访问无此需求 |
| `pyjwt` 等 JWT 库 | stdlib `hmac` + `hashlib` 够用，避免依赖膨胀 |
| Cookie + HttpOnly | 当前 H5 同源，不需；XSS 风险由"不内嵌用户输入渲染"对冲 |
| IP 白名单 | 调查员可能在不同网络（家庭/单位/移动）下访问，不灵活 |

## 影响

- **隐私**：白名单 JSON 真人手机号不进 git（`.gitignore` + `.whitelist.example.json` 模板）
- **运维**：admin 手工编辑 JSON 文件即可增减用户，热生效
- **限制**：
  - 多设备同登覆盖前者（无服务端会话表）
  - brute force 未防护（手机号 11 位 + 白名单外拒绝，攻击面小）
  - 生产必须设 `LSX_AUTH_SECRET`（启动 warning 兜底）
- **回归**：`scripts/run_eval.py` 加 `--phone` 参数拿 token，否则 401
