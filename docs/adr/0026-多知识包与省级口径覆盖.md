# 多知识包与省级口径覆盖

**状态：已采用（2026-10-15）**

系统走向全国后，不同省可能对同一指标采用不同解释。项目决定把现有单一知识库拆为一个全国基础知识包和若干省级知识包：全国包承载统一制度和通用规则，省级包只承载地方差异，并通过稳定 `rule_key` 显式覆盖全国同规则内容。每个知识包独立构建、发布和回滚，问答根据账号当前 `province_code` 动态解析兼容版本组合，不用账号级手工绑定。

## 考虑过的方案

- 每省复制完整知识库：会产生大量重复内容，年度制度同步困难，因此不采用。
- 所有包共用一个索引后按 `kb_id` 过滤：容易跨省误召回，且与当前全量精确向量缓存、独立重建和回滚需求冲突，因此不采用。
- 允许账号手工指定知识包：会绕过省级口径、污染热点和审计，因此第一版不采用。

## 主要后果

- `knowledge-base/` 按知识包组织；`indicator_catalog.json` 等制度目录保持全国共享。
- 新建独立知识包注册库，保存包、版本、省份绑定、发布记录和审计。
- 省份绑定使用省级行政区划代码，与标准调查点目录解耦，全国上线按省分批进行。
- 构建在校验、索引和 Eval 全部通过后生成不可变版本；后台只发布或回滚。
- 问答优先使用省级覆盖内容，来源展示省级依据；查询日志记录实际知识包版本。
- 全国包升级后，省级包未复核的省份继续使用最后一个兼容版本组合。
