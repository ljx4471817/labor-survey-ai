# ADR 0021：标准调查点选择与账号类型表单

## 状态

**已采用（2026-09-01）**，先约束新增流程；存量编辑采用旧数据兼容策略。

## 背景

白名单新增人员时，市 / 县 / 乡镇 / 社区原先由管理员手填，拼写不一致和越范围填写的风险较大。同时「管理员层级」与「系统职能」的表述不够直观，且不直观的层级与职能组合可能造成权限误配。现有运营模式下，白名单由开发者通过 LLM 统一导入，后台只需做个别增减，网页 CSV 批量导入没有实际使用场景。

## 决策

### 1. 标准调查点是唯一可选数据源

- 将 `贵州省所有调查点数据.xlsx` 转换为 `backend/data/region_points.json`，当前 719 条，字段包含 `province / city / county / township / community`。
- 后端通过 `GET /api/admin/whitelist/region-points` 下发标准点，并按操作人 `region_scope` 过滤；系统管理员可看全省。
- 新增前端四级下拉全部可搜索且级联过滤；不允许手填兜底。
- 后端新增接口强制校验：省级只认贵州省；市级必须选标准市；区县必须选标准市县；调查员必须精确匹配一条标准调查点。
- 弹窗固定提示「没有对应调查点？反馈给系统管理员」，不提供手工输入通道。

### 2. 表单语义改为「管理范围 × 账号类型」

- `admin_level` 的用户界面表述改为「管理范围」，单选：省级 / 市级 / 区县 / 调查员。
- `sys_role` 的用户界面表述改为「账号类型」，单选：普通用户 / 业务管理员 / 系统管理员。
- 字段顺序调整为：管理范围、账号类型、手机号 / 姓名、区域、备注。
- 账号类型仅系统管理员可设；其他操作者按管理范围自动展示结果。
- 合法组合固定为：省级 → 业务管理员或系统管理员；市级 / 区县 → 业务管理员；调查员 → 普通用户。选择系统管理员时管理范围锁定省级。
- 系统管理员新增或编辑变更为系统管理员时，前端增加二次确认。

### 3. 存量数据只做触碰式清洗

编辑时如果旧区域不在标准数据中，下拉框黄色标记「旧数据，请重新选择」；只要不修改区域，仍允许原样保存。一旦修改区域或管理范围，立即走新校验。这样避免一次性迁移 66 个未匹配的存量调查员，也防止旧数据被静默改错。

### 4. 批量导入入口停用

前端删除 CSV 批量导入按钮和弹窗；后端 `POST /api/admin/whitelist/import-csv` 返回 403，防止直连接口绕过页面。导出和批量停用不受影响。

## 影响

- **数据源更新**：调查点变化时先更新源 Excel，再运行 `scripts/convert_region_points.py` 重新生成 JSON；不要直接改网页或绕过后端校验。
- **兼容**：`city` 在省级 / 系统管理员场景允许为空；四级字段仍完整保留在 schema 中，`province` 已预留后续跨省扩展。
- **安全**：新增和编辑都做服务端区域校验，前端过滤只是交互优化，不是权限边界。
