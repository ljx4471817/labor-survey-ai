# ADR 0001：前端选型

## 状态

**已反转（2026-06-21）**：原决策 2026-06-15 为"微信小程序原生开发"，2026-06-21 改为 **H5 单页应用（嵌入 FastAPI 静态资源）**。

## 变更记录

| 日期 | 决策 | 备注 |
|------|------|------|
| 2026-06-15 | 微信小程序原生开发 | 初版 |
| 2026-06-21 | **H5 单页应用** | 见下方「反转理由」 |

## 背景

需要为辅助调查员提供一个"扫码即用"的查询工具。载体需要满足：
- 无需安装
- 基层用户熟悉（用微信生态）
- 与后端 API 通信支持文字/语音/流式
- 支持离线模式

## 当前决策（2026-06-21）

**H5 单页应用，由 FastAPI 直接挂载静态文件服务。**

- 入口：`backend/static/index.html`（单文件，含全部 CSS/JS）
- 部署：`uvicorn app.main:app` 同进程提供 `/static/` 和 `/api/*`，无需单独前端服务器
- API 调用：`/api/chat`、`/api/feedback`（`/api/voice/stream` **2026-06-21 已停用**）
- 移动端：响应式 CSS，含 iOS safe-area 适配
- 触达：通过 Cloudflare Tunnel 暴露公网 → 微信内直接打开链接

## 反转理由（2026-06-21）

1. **MVP 速度优先**：H5 单文件即可完整支持文本/反馈两条核心流；小程序需要 WXML+WXSS+JS+JSON 四件套，加上构建工具链，开发和调试成本是 H5 的 3-5 倍
2. **本地验证更直接**：浏览器即开即测，不用打开微信开发者工具、不用扫码预览
3. **讯飞 WebSocket 原已可用（2026-06-21 起停用）**：`backend/app/api/_xunfei_auth.py` + `voice.py` 鉴权与流式代码保留，但用户决定输入法自带语音转写已够用，UI 与路由已隐藏/注释
4. **部署更轻量**：H5 走 Cloudflare Tunnel 出公网，零额外构建；小程序还要走微信审核，迭代周期长
5. **离线能力原本就被低估**：原 ADR 把"离线"列为 H5 短板，但 MVP 阶段 RAG 回答依赖在线 LLM，"离线"本身不成立 —— 这一条失分权重下降

## 备选分析（2026-06-15 当时考虑的方案）

### 备选 1：H5 网页（原被排除，现已采纳）
- ✅ 跨平台、无需审核
- ✅ 浏览器即可开发调试
- ✅ 零构建工具链，单文件即服务
- ⚠️ 国内 PWA 兼容性差（但本项目用普通 Web App，不依赖 PWA）
- ⚠️ 触达路径长（要复制链接或发二维码）

### 备选 2：Taro / uni-app 跨端框架
- ✅ 一套代码多端运行（小程序 + H5 + App）
- ❌ 引入学习成本与运行时开销
- ❌ 流式输出、ASR 等场景的跨端兼容需要额外处理
- ❌ MVP 阶段不需要跨端，过度设计

### 备选 3：原生 App（iOS/Android）
- ✅ 性能最强、API 最全
- ❌ 需要应用商店审核
- ❌ 安装门槛高，与"扫码即用"目标矛盾

### 备选 4：微信小程序原生开发（2026-06-15 采纳，2026-06-21 反转）
- ✅ 触达最短（微信内一搜即用）
- ❌ 需要 WXML/WXSS/JS/JSON 四件套和构建链
- ❌ 调试要依赖微信开发者工具
- ❌ API 审核周期长
- ❌ WebSocket 兼容性需要单独验证

## 影响

- 前端代码位置：`backend/static/`，由 FastAPI 挂载
- 不引入 npm / 打包工具，主页保持单文件
- iOS / Android / 桌面浏览器共用一份代码
- 公网触达依赖 Cloudflare Tunnel（待部署）
- ADR 0001 中"微信小程序"相关配置（`miniprogram/.miniprogram/`、`miniprogram/dist/` 等 `.gitignore` 项）将在清理由阶段移除

## 考虑的备选

### 备选 1：H5 网页
- ✅ 跨平台、无需审核
- ❌ 无法使用微信原生能力（录音、扫一扫、支付等）
- ❌ 离线能力弱（PWA 在国内的兼容性差）
- ❌ 用户触达路径长（要复制链接）

### 备选 2：Taro / uni-app 跨端框架
- ✅ 一套代码多端运行（小程序 + H5 + App）
- ❌ 引入学习成本与运行时开销
- ❌ 流式输出、ASR 等场景的跨端兼容需要额外处理
- ❌ MVP 阶段不需要跨端，过度设计

### 备选 3：原生 App（iOS/Android）
- ✅ 性能最强、API 最全
- ❌ 需要应用商店审核
- ❌ 安装门槛高，与"扫码即用"目标矛盾

## 影响

- 使用 WXML/WXSS/JS，不引入 TypeScript 编译器（除非必要）
- 工具函数放 `miniprogram/utils/`，页面逻辑放 `pages/<page>/`
- 第三方依赖限制：能不用就不用，主包 < 2MB
- 流式输出主推 WebSocket（兼容性优于 chunked transfer）
