# ADR 0001：前端选型

## 状态

已确认（2026-06-15）

## 背景

需要为辅助调查员提供一个"扫码即用"的查询工具。载体需要满足：
- 无需安装
- 基层用户熟悉（用微信生态）
- 与后端 API 通信支持文字/语音/流式
- 支持离线模式

## 决策

**微信小程序原生开发**。

## 考虑的备选

### 备选 1：H5 网页
- ✅ 跨平台、无需审核
- ❌ 无法使用微信原生能力（录音、扫一扫、支付等）
- ❌ 离线能力弱（PWA 在国内的兼容性差）
- ❌ 用户触达路径长（要复制链接）

### 备选 2：Taro / uni-app 跨端框架
- ✅ 一套代码多端运行（小程序 + H5 + App）
- ❌ 引入学习成本与运行时开销
- ❌ 流式输出、ASR 等场景的跨端兼容需要额外处理
- ❌ MVP 阶段不需要跨端，过度设计

### 备选 3：原生 App（iOS/Android）
- ✅ 性能最强、API 最全
- ❌ 需要应用商店审核
- ❌ 安装门槛高，与"扫码即用"目标矛盾

## 影响

- 使用 WXML/WXSS/JS，不引入 TypeScript 编译器（除非必要）
- 工具函数放 `miniprogram/utils/`，页面逻辑放 `pages/<page>/`
- 第三方依赖限制：能不用就不用，主包 < 2MB
- 流式输出主推 WebSocket（兼容性优于 chunked transfer）
