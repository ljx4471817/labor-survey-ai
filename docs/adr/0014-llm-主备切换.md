# ADR 0014 — LLM primary/fallback routing with quota monitoring (MiniMax / DeepSeek)

> Status: adopted (2026-08-12)
> Trigger: cost control on the MiniMax Token Plan (5h rolling quota); avoid hitting the cap and degrading service for enumerators during busy periods.
> Decision maker: developer

## Background

The MiniMax Token Plan Starter subscription is billed against a 5h rolling window (plus a 7d weekly window), and API usage counts against the plan. When the 5h window is exhausted, the account is rate-limited (`current_interval_status=0`) and the H5 assistant becomes unusable exactly when enumerators need it most.

Goal: keep MiniMax M2.7-highspeed as the primary model for answer quality, switch to the cheaper DeepSeek flash (`deepseek-v4-flash`) when the plan approaches its cap, and switch back once the rolling windows slide.

## Decision

A runtime LLM router with hysteresis, driven by a background quota monitor.

### 1. Routing

- `backend/app/services/llm_router.py` persists the active provider in `backend/data/llm_route.json`.
- `backend/app/rag/llm.py` resolves provider/model/URL at call time from that state (no restart needed); MiniMax M2.x `<think>` blocks are stripped from responses.

### 2. Hysteresis (anti-flapping)

- Switch away: 5h used >= 85% OR 7d used >= 90% -> DeepSeek.
- Switch back: 5h used < 70% AND 7d used < 85% AND >= 30 min since last switch -> MiniMax.
- The 5h/7d windows are rolling (no fixed reset); "switch back" is driven by usage dropping, not a clock.

### 3. Quota monitoring

- `backend/app/services/minimax_quota.py` queries the plan endpoint with `Authorization: Bearer <MINIMAX_API_KEY>` — no `_token` cookie, no login session, no expiry (zero maintenance). Endpoint overridable via `MINIMAX_QUOTA_URL`.
- A daemon thread (`llm_switch_job.py`, started in `backend/app/main.py`) checks every 10 minutes and persists state.
- Fail-safe: 3 consecutive quota-check failures force a switch to DeepSeek so MiniMax quota is never burned blind while monitoring is down; responses without usable usage data also count as failures; normal hysteresis resumes after recovery.

### 4. Observability

- `GET /api/admin/llm/route` returns provider/model/5h/7d usage/last check/last error; the dashboard "usage" tab shows a current-model card with a manual refresh button.

## Alternatives considered

| Option | Why not |
|---|---|
| `_token` cookie + manual refresh | Expires in days; needs human intervention |
| Playwright session auto-refresh | Adds a browser dependency and login-session maintenance |
| Restart process / rewrite settings on switch | Restart disrupts live users; state file is simpler |
| External cron / task scheduler | Extra moving part vs the in-process daemon thread |

## Consequences

- Positive: cost control with hysteresis; zero token maintenance; state visible on the dashboard.
- Negative: quota endpoints are unofficial and could change (mitigated by `MINIMAX_QUOTA_URL`).
- Neutral: adds a background thread per worker; 31+ unit tests guard the decision logic.
