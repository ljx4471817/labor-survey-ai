# ADR 0007：多轮对话上下文

## 状态

**已采用（2026-06-24）**

## 背景

调查员常问后续追问："那种情况呢"、"为什么不算"、"合同还没签呢"。这些短追问：

- 单独检索召回率低（缺主语/上下文）
- LLM 答得不准（无前置语境）
- 用户体验割裂（要重述一遍）

## 决策

**最多 4 轮历史上下文 + 短问句拼接检索 + prompt 注入 history_context。**

### 三件套

#### 1. API 层：`ChatRequest.history: list[ChatMessage]`

```python
class ChatMessage(BaseModel):
    role: Literal["user", "assistant"]
    content: str = Field(..., max_length=4000)

class ChatRequest(BaseModel):
    message: str
    history: list[ChatMessage] = Field(default_factory=list, max_length=4)
```

- 单条 message 最长 4000 字（防滥用）
- history 最多 4 条（**轮 = 一来一回 = 2 条 message**，即 2 轮对话 = 4 条 message）
- 前端每次发送附带最近 4 条，前端不再缓存（页面刷新即丢，符合"会话级而非持久"语义）

#### 2. 检索层：`merge_query_with_history(query, history)`

**方案 X**（commit `de75c90`，2026-06-24）：

| 条件 | 行为 |
|------|------|
| 当前 query ≥ 8 字 | 直接用 query 检索（不污染） |
| 当前 query < 8 字 | 用最近一条 user message 拼接兜底检索 |

为什么不直接拼接所有历史？→ 多轮语义漂移，拼接可能引入噪声；用"最近一条 user message"做兜底已够。

#### 3. Prompt 层：`history_context` 注入

模板位置：`backend/app/rag/prompts.py`

```
[history_context]
{compressed_history}
[/history_context]
[当前问题]
{current_query}
```

- `history_context` 拼在 system prompt 末尾
- 历史 message 截断到 200 字/条防 token 膨胀
- LLM 看到 history 后能理解"那种情况"指代什么

### history 非空跳过模糊追问

`backend/app/api/chat.py` 在 `merge_query_with_history` 之前判断：

```python
if req.history:
    # 多轮模式：不触发"能否具体说说"的模糊追问
    pass
else:
    # 单轮模式：保留原模糊追问行为
    ...
```

理由：用户在多轮上下文里追问 "为什么不算" 是合理的；单轮追问可能是问题不清。

## 考虑过的备选

| 方案 | 否决理由 |
|------|----------|
| 全量历史拼接到 query 检索 | 多轮语义漂移，检索噪声大 |
| 服务端持久化 session | 单人项目不需要；刷新即丢符合预期 |
| LangChain / LlamaIndex ConversationBuffer | 引入框架 + 多一层抽象；项目坚持零外部依赖风格 |
| 上下文窗口无限制 | token 成本失控；4 轮是经验值 |
| 多轮也走模糊追问 | 用户体验割裂，明明上文清楚还要被反问 |

## 影响

- **token 成本**：每次请求 history 截断 4 条 × 200 字 ≈ 800 字额外输入
- **前端**：每次 fetch 把 localStorage 里最近 4 条 message 一起 POST
- **回归测试**：`eval_set.json` 加 `history` 字段，eval-101/102 锁定多轮场景关键指标
- **可观测**：L 日志可看 `merge_query_with_history` 是否触发拼接兜底
