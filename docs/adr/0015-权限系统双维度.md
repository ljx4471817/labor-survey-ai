# ADR 0015：权限系统双维度改造（admin_level × sys_role + 分级网页维护）

## 状态

**已采用（2026-08-13）**，实现见 PRD-权限系统改造.md。

## 背景

1. `docs/权限表.xlsx` 曾是唯一事实源，每月调查员轮换需开发者手工改 Excel 再跑同步脚本，无法支撑全省铺开。
2. `admin_level`（省级/市级/区县/调查员）一个字段同时承担「业务层级」与「功能权限」，概念混淆；「系统管理员」没有独立建模。
3. 后台安全缺口：除测验和 LLM 切换外，`/api/admin/*` 只校验登录（`require_user`），任何白名单调查员知道 URL 即可调用。
4. 离职账号 token 在 24h TTL 内仍可用：`require_user` 只验签名不查 active。
5. 无审计，无法追责；区县无管理入口。

## 决策

**双维度权限模型 + whitelist.db 实时唯一事实源 + 全后台角色校验 + 审计表。**

### 1. 双维度

| 维度 | 取值 | 含义 |
|---|---|---|
| `admin_level`（现有字段） | 省级 / 市级 / 区县 / 调查员 | 业务管辖范围 |
| `sys_role`（新增字段） | 系统管理员 / 业务管理员 / 普通用户 | 系统职能（仅三种取值，不扩展） |

- 回填规则：`admin_level IN (省级,市级,区县)` → 业务管理员；调查员 → 普通用户。
- `.env` 配置 `LSX_SYSTEM_ADMIN_PHONE` → 该号码恒为系统管理员且 active=1（防业务层级推导覆盖）；
  缺失则启动 warning，系统管理员专属功能 403。

### 2. Schema 变更（本 ADR 即确认）

```sql
ALTER TABLE whitelist ADD COLUMN sys_role TEXT NOT NULL DEFAULT '普通用户';
CREATE TABLE IF NOT EXISTS whitelist_audit (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    actor_phone TEXT NOT NULL, actor_name TEXT,
    action TEXT NOT NULL,      -- create/update/disable/enable/batch_disable/sys_role_change/import
    target_phone TEXT NOT NULL, before_json TEXT, after_json TEXT,
    created_at TEXT NOT NULL
);
```

- 迁移幂等：首次连接自动执行（`whitelist_db._migrate`），另提供 `scripts/migrate_whitelist_rbac.py --dry-run/--apply`（dry-run 输出 diff，apply 先备份）。
- 审计保留 12 个月（`cleanup_audit`）。

### 3. 鉴权依赖（`backend/app/infra/auth.py`）

| 依赖 | 放行条件 | 用途 |
|---|---|---|
| `require_user` | 登录 + **每次请求查 whitelist 确认 active**（停用即时生效） | 对话/答题 |
| `require_whitelist_admin` | `sys_role ∈ {系统管理员, 业务管理员}`，返回完整 user（含区域） | 白名单/使用统计 |
| `require_quiz_admin` | `sys_role ∈ {系统管理员, 业务管理员}` 且 `admin_level ∈ {省级, 市级}` | 测验管理 |
| `require_quiz_stats` | `sys_role ∈ {系统管理员, 业务管理员}`（任意层级） | 完成率只读统计 |
| `require_system_admin` | `sys_role = 系统管理员` | 反馈/KB/LLM/审计/CSV 导入 |

> **解释**：PRD §5 简表把完成率统计写成 `require_quiz_admin`，但 §2 目标与 §3.2 功能矩阵明确
> 「区县业务管理员可查看本区域测验完成率（只读）」。本 ADR 以矩阵为准，拆出 `require_quiz_stats`：
> 只读统计对任意层级业务管理员放行（后端按 scope 过滤），管理/下发仍限省级/市级。

### 4. 范围规则

- `region_scope(actor)`：系统管理员 → 无限制；省级 → (province)；市级 → (province, city)；区县 → (province, city, county)。
- `in_scope(actor, target)`：目标记录区域必须在管辖范围内。
- 业务管理员不可操作：系统管理员账号、保护测试号 13985000001-4、区外数据；不可设置/修改 `sys_role`（API 强制按 admin_level 推导）。
- 白名单可设层级：省级→{市级,区县,调查员}；市级→{区县,调查员}；区县→{调查员}。

### 5. 前端

- `login.html`：按 `sys_role` 路由——系统管理员/市级以上业务管理员 → `/quiz-admin`；区县业务管理员 → `/dashboard`（统一后台，白名单为其中模块；`/whitelist-admin` 独立页保留兼容）；普通用户 → `/`。
- `whitelist.html`：角色化（whoami 探测；区县只读本县 + 仅调查员 + CSV 导出；市级本市区县/调查员；系统管理员全量 + sys_role 下拉 + 审计 tab + CSV 导入）；新增多选批量停用、行内启用、导出按钮；支持 `?embed=1` 嵌入模式（隐藏独立页头/页脚）。
- `dashboard.html`：统一后台入口——系统管理员全量（KB/反馈/LLM/使用侧发现）；业务管理员只见本区域「使用情况 + 完成率」只读 tab；新增「白名单管理」模块 tab（iframe 懒加载 `/whitelist-admin?embed=1`，同源复用 token/角色，业务管理员与系统管理员均可见），顶部「白名单管理」链接切到该 tab。
- `quiz_admin.html` / `quiz-stats.html`：市级业务管理员目标/统计只显示本市；系统管理员/省级不限；区县可只读完成率。

## 考虑过的备选

| 方案 | 否决理由 |
|------|----------|
| 仅扩展 admin_level 枚举（加"系统管理员"） | 仍混淆业务层级与职能，且系统管理员天然无区域 |
| 继续 xlsx 手工同步 | 无法支撑全省铺开；网页分级维护是目标 |
| require_user 只验签名 | 离职账号 24h 内仍可用，安全缺口 |

## 影响

- **运维**：`LSX_SYSTEM_ADMIN_PHONE` 必须在 `.env` 配置；生产迁移先跑 `migrate_whitelist_rbac.py --dry-run` 再 `--apply`。
- **兼容**：`sync_whitelist_xlsx.py` 标注 DEPRECATED（仅初始导入/恢复），避免旧 xlsx 覆盖线上。
- **安全**：手机号日志沿用 `phone[:3]****` 脱敏；所有写操作写审计。
- **回归**：`pytest tests/ -q` 全绿 + `scripts/run_eval.py --phone 13985000001` 通过。
