# 协作手册 · 同事版（故事集）

> 主角**小王**是新来的同事，维护者叫**老张**，小王的 AI 助手叫**小智**。
> 六个故事覆盖你日常会遇到的所有场景。按钮名都写在故事里，忘了就回来翻。

## 故事一：小王第一次进实验室

小王想给老张的项目干活。老张说："先注册个 GitHub 账号，把**用户名**发我——密码任何人都不需要。"

小王注册好发了用户名，几分钟后收到邀请邮件，点接受，就成了仓库协作者。

接下来搭环境。小王对小智说："克隆仓库 ljx4471817/labor-survey-ai，装好后端依赖，照着根目录的 .env.example 生成 .env，重建知识库索引，最后把本地服务跑起来。"

小智一顿操作后提醒："有个文件得你来——打开 `.env`，填入**你自己**申请的 API key 和系统管理员手机号。"

小王填完，用老张提前加进白名单的测试号登录，看到了熟悉的页面。他顺手想把 .env 也存进仓库"图个保险"，小智立刻拦住："这文件装着你的钥匙，永远不进仓库、不发群、不贴 Issue。丢了可以重填，泄了要全员换锁。"

> 小王记在本子上：给老张发用户名；key 只填在 .env；.env 永远不进仓库。

## 故事二：小王的第一个功能

周一，小王要做"导出周报表"。他对小智说了四句话：

1. "同步主干，开一条新分支，叫 xiaowang/export-report。"
2. "实现导出周报表，补上单元测试，跑全量测试给我看结果。"——257 项全绿
3. "提交，说明写 feat: 新增周报表导出。"
4. "推送到 GitHub，然后帮我开 PR。"

小智推完扔来一个链接。小王点开，看到一个页面：左边 **base** 是 main，右边 **compare** 是自己的分支，中间一行绿字 **Able to merge**。

"绿字=测试通过吧？"小王问。
"不。那只说明两条分支没改到同一处、没有冲突。真正的测试要等你点了创建按钮才开始。"

小王往下滚，点绿色 **Create pull request**，跳到 PR 页面后填上"改了什么、为什么改、怎么验证的"，再点一次 **Create pull request**。

页面下方出现一个转圈的小圆点——CI 机器人正在一台全新的虚拟电脑上从头跑全部测试。两分钟后，圆点变成绿勾 **All checks have passed**。

"要是红叉呢？"
"点开红叉，把红色报错整段复制给我。我修完重新推送到同一条分支，PR 自动更新、自动重跑。**千万别重新开一个 PR**。"

绿勾之后的事归老张。他批准合并后，小王对小智说："切回主干，同步最新，删掉本地旧分支。"收工。

> 回放：同步→开分支→开发+测试全绿→提交→推送→点链接→Create pull request→等绿勾→等老张合→同步主干收工。

## 故事三：小王挨了批

老张在小王的 PR 里留言："日期格式硬编码了，换掉。"

小王打开 PR，点 **Files changed** 标签找到评论，对小智说："按老张的意见改。"改完，小智把新提交推到**同一条分支**——PR 自动长出新提交，评论旁亮起"已解决"。

小王学到的：PR 是活的，改完往原分支推就行。

## 故事四：小王和小李撞车

周三，小王推送被拒。小智解释："小李刚合并的功能也动了这行，你们撞车了。我来把主干的新改动接进来。"

小智处理完，列出三处冲突："每处你决定留谁的。"小王逐个看过，有一处两人逻辑都要保留，让小智手工合了。确认没漏掉任何一方，重新推送成功。

> 回放：推送被拒→让 AI"同步主干重放我的改动"→逐处确认保留哪边→继续推送。

## 故事五：小王发现系统病了

周四，小王发现热点问题列表打不开。试了三次、截了图，然后：仓库首页 → 顶部 **Issues** → 绿色 **New issue** → 标题"热点问题列表 500" → 正文按模板填现象、复现步骤、期望结果、截图 → 标签选 **bug** → **Submit new issue**。

一周后他修好了，在 PR 描述里写"Closes #23"。合并那一刻，Issue 自动关闭，因果一条线。

## 故事六：小王当了一次裁判

老张让小王帮忙看别人的 PR。小王点开 **Files changed** 逐块读，有行看不懂，点行号旁的 **+** 号提问。全看完，右上 **Review changes** → 写总评 → 选 **Request changes** → **Submit review**。作者改完重推后，小王再来，这次选了 **Approve**。

"批准是责任，不是点赞。"小智说。

## 附：三条底线

1. `.env`、任何 `.db`、API key、真实手机号：不进仓库、不发群、不进 Issue/PR
2. 仓库是公开的，内部敏感资料不上传
3. main 推不上去不是故障，是门锁——走 PR
